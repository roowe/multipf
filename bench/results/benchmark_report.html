关键发现（修复后）

  • 最高吞吐 Zig 以 85,283 QPS 位居第一（50 并发），C++ 83,459（200 并发）与 C 83,421（100 并发）紧随其后，Rust 80,768。
  • 单核最强 C / C++ 用单线程事件循环（kqueue/epoll）只占约 90% 的单核 CPU，就达到与多线程 Rust/Zig 同水平的吞吐，是全场 CPU 效率最高的实现。
  • 最低内存 C 在 50 并发 10.2MB，200 并发 17.6MB；C++ 为 10.4MB / 23.8MB。两者靠“缓冲满则不读”的背压模型把每连接内存控制在 32KB 上限。
  • 最低延迟 50 并发下 Zig 0.586ms、C++ 0.607ms、C 0.619ms、Rust 0.637ms；200 并发高性能实现 avg 均在 2.4-2.7ms。
  • 多核 vs 单核 Rust/Zig/Go 会吃满多核（200-425% CPU）；C/C++/TypeScript 是单线程模型，只用一个核。若要多核，需 SO_REUSEPORT + 每线程一个事件循环。
  • Elixir 改善显著 修复后 Elixir 全并发零错误，200 并发 67.6K QPS，但 CPU 消耗最高（699%），内存也偏大（71.6MB）。
  • Python 瓶颈 Python 受 GIL 限制，峰值 31.3K QPS，约为其他实现的 1/3；200 并发 p99 达 24.4ms。
  • 全并发零错误 8 种语言 × 4 个并发级别共 32 个测试场景，全部零连接错误。
  • 数据波动 单次 10 秒采样，轮次间峰值 QPS 波动约 ±5-8%，同档位排名可能小幅变化。

结论与建议

  • 多核吞吐首选 Rust / Zig：85K QPS、最低延迟，适合对吞吐和尾延迟要求极高的场景。
  • 单核极致 / 资源受限 C / C++：一个核跑 81K QPS、内存不到 20MB，适合边缘节点、容器配额受限或希望按核水平扩展的场景。
  • 生产均衡 Go：75K QPS + 零错误 + 生态成熟，CPU 开销较高但工程成本最低。
  • I/O 密集型 TypeScript：单线程事件循环稳定可靠，68K QPS。
  • 原型 / 低流量 Python：GIL 限制明显，性能约为其他实现的 1/3。
